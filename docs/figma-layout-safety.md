# Figma 레이아웃 틀어짐 방지 규칙

> use_figma(Plugin API)로 노드를 만들거나 고칠 때 지킨다. figma-builder 의 모든 STAGE와 게이트 밖 시안 탐색에 공통으로 적용한다.
> 배경: 1안 v2 시안(2026-11)에서 서버 렌더(get_screenshot)는 정상인데 **Figma 앱에서는 잘리거나 밀려 보이는** 문제가 반복됐다. 아래 규칙은 그때 확인한 원인별로 정리했다.

## 1. 인스턴스 크기는 rescale로 바꾸지 않는다

- **인스턴스에 `rescale()`을 쓰지 않는다.** 오토레이아웃이 아닌 벡터 컴포넌트(로고 등)에서는 크기 오버라이드가 남지 않는다(`overrides`에 `width`/`height`가 없음). 서버 렌더는 정상으로 보이지만, 앱에서는 원본 크기 벡터가 작은 상자 안에 그려져 잘린다.
  - 실제 사례: `Logo/ALL# BI (올샵)` 인스턴스를 111×44로 줄였더니 앱에서 "(올샵" 부분이 잘렸다.
- **크기가 다르게 필요하면 `Size=` 변형 컴포넌트를 만든다.** 컴포넌트 자체를 복제해 `rescale()`하면 자식 벡터의 실제 크기가 바뀐다. 인스턴스는 그 변형을 **원래 크기 그대로** 쓴다.
  - 예: `Logo/ALL# Mark` Size=28(GNB용), `Logo/ALL# BI (올샵)` Size=44(로그인용)
- 아이콘 인스턴스 크기를 바꾸는 것은 허용한다. 다만 아이콘 컴포넌트의 자식 벡터가 `constraints = SCALE`이어야 하고, 아래 §7 검사를 통과해야 한다.

## 2. strokesIncludedInLayout 은 항상 false

- 오토레이아웃 프레임과 컴포넌트를 만들 때 `strokesIncludedInLayout = false`로 둔다. 헬퍼 함수에서 `true`로 두지 않는다.
- `true`이면 테두리 두께가 레이아웃 폭 계산에 들어간다.
  - 실제 사례: 카드 안쪽 폭이 420이 아니라 418로 계산됐다. Input 컴포넌트도 `true`라서 앱에서 입력칸이 부모보다 넓게 그려지고 오른쪽 테두리가 잘렸다.

## 3. 레이아웃용 래퍼는 내용을 자르지 않는다

- 배경과 테두리가 없는 레이아웃용 래퍼(필드 묶음, 행, 열)는 `clipsContent = false`로 둔다.
- 경계에 딱 붙은 자식의 INSIDE 테두리는 앱의 확대·축소 배율에 따라 1px씩 잘려 보인다.
- 내용을 자르는 것(`clipsContent = true`)은 다음 경우에만 쓴다.
  - 실제 스크롤 viewport
  - radius가 있는 이미지 컨테이너
  - 화면 최상위 프레임
  - 장식 레이어를 잘라야 하는 패널

## 4. 사이징은 부모에 붙인 뒤 지정하고, 축을 바꾸면 다시 지정한다

- 순서를 지킨다: `appendChild` 다음에 `layoutSizingHorizontal/Vertical = 'FILL' | 'HUG'`.
- FILL을 지정한 뒤에 `resize()`를 부르지 않는다. `resize()`를 부르면 FIXED로 돌아간다.
- **이미 자식이 있는 프레임의 `layoutMode` 축을 바꾸면**(VERTICAL ↔ HORIZONTAL) 자식의 사이징을 전부 다시 지정한다.
  - 실제 사례: 로그인 레이아웃을 세로에서 가로로 바꿨더니, 위 막대(TopBar)와 푸터의 높이가 1080으로 늘어나 화면이 밀렸다.
- 빈 오토레이아웃 프레임은 기본 높이 100이 잡힌다. 간격용 스페이서는 `height 1` + FILL 헬퍼로만 만든다.

## 5. 색은 변수로만, 반투명은 alpha 변수로

- 반투명 면에 **페인트 `opacity`를 쓰지 않는다.**
  - 실제 사례: `{...boundPaint, opacity}`처럼 바인딩된 페인트를 펼쳐 쓰면 opacity가 사라졌다. opacity를 바인딩 입력에 넣어도 Dark 모드 프레임에서는 불투명하게 렌더됐다.
- 대신 알파값을 가진 primitive를 만들고 semantic에 연결해 쓴다.
  - 예: `alpha/white-08` → `brand/tile`
- `setBoundVariableForPaint`에 넣는 자리표시 색은 실제 값과 비슷한 색으로 둔다. 검정(0,0,0)으로 두면 렌더 캐시가 검정으로 남는 경우가 있었다.

## 6. clone 은 현재 페이지에 생길 수 있다

- 최상위 프레임을 `clone()`하면 원본 페이지가 아니라 `figma.currentPage`에 생길 수 있다.
  - 실제 사례: 다크 로그인 복제본이 `00 기존 1안 (참고)` 페이지에 만들어졌다.
- 복제한 뒤에는 대상 페이지에 `appendChild`로 명시적으로 넣고, `parent`를 확인한다. 복제본 위치가 다른 프레임과 겹치지 않는지도 확인한다.

## 7. 끝내기 전 구조 검사 (스크린샷만으로 판단하지 않는다)

서버 렌더(get_screenshot)와 앱 렌더가 다를 수 있다. 스크린샷이 정상이어도 아래 다섯 가지를 use_figma로 검사하고, 결과가 모두 0건이어야 한다.

1. 크기가 원본 컴포넌트와 다른데 `overrides`에 `width`/`height`가 없는 인스턴스. 아이콘 외에는 0건이어야 한다.
2. `strokesIncludedInLayout === true`인 프레임이나 컴포넌트
3. `clipsContent`인 부모의 경계를 넘는 자식. 의도적인 겹침(예: MDI 선택 탭의 1px)은 이름이나 메모로 표시한다.
4. 레이아웃용 래퍼(배경·테두리 없음)인데 `clipsContent = true`이고, 자식이 경계에 붙어 있는 경우
5. 오토레이아웃 인스턴스인데 자식이 자기 경계 밖에 있는 경우. 인스턴스 폭은 바뀌었는데 안쪽 레이아웃이 다시 계산되지 않은 상태다.
   - 실제 사례: C안 입력칸이 440으로 줄었는데 안쪽 Value가 620 폭으로 남아, 화살표가 칸 밖으로 밀렸다.
   - 고치는 법: `layoutSizingHorizontal = 'FIXED'` → `resize(w+1)` → `resize(w)` → 원래 사이징으로 되돌리기. 그래도 안 되면 새로 생성한다.
   - 부모 폭을 바꾼 직후에는 이 검사를 반드시 돌린다.

검사한 뒤 화면 단위 스크린샷과 문제가 된 노드 단위 스크린샷을 함께 확인한다.

## 8. 옮기고 고친 노드를 재사용하지 않는다 — 화면을 새로 그릴 때는 새로 만든다

- **화면을 재설계할 때는 기존 폼·필드 노드를 옮겨 쓰지 않는다.** 현재 컴포넌트에서 인스턴스를 새로 만든다.
  - 여러 번 부모를 바꾸고(reparent), 폭을 바꾸고, 부모의 레이아웃 축이 바뀐 노드는 서버 데이터가 정상이어도 앱에서 다르게 그려질 수 있다.
  - 실제 사례: 로그인 입력칸이 Plugin API, 메타데이터, design context 세 곳 모두에서 폭 400, 테두리 네 변 정상이었다. 그런데 앱에서는 오른쪽 테두리가 두 번이나 잘렸다. 해당 노드는 첫 시안 → 중앙 카드 → 분할형으로 세 번 옮겨졌고, 복제본(B/C안·다크)도 같은 상태를 물려받았다.
- **복제(clone)도 옮긴 노드의 상태를 그대로 물려준다.** 다른 시안에서 같은 폼이 필요하면 복제하지 말고, 같은 생성 함수로 새로 만든다.
- **서버 렌더와 앱 렌더가 다를 때는 같은 노드를 두 번 이상 패치하지 않는다.** 순서는 이렇다.
  1. §7 구조 검사와 `get_design_context`로 데이터를 확인한다.
  2. 데이터가 정상인데 앱에서만 깨지면 **해당 노드를 새로 생성해 교체**한다.
  3. 사용자에게 앱에서 그 노드를 선택했을 때 보이는 W/H 값을 확인해 달라고 요청한다.
- 새 인스턴스는 메인 컴포넌트 크기(예: Input 높이 32)로 생긴다. 필요한 높이는 `resize(w, h)`로 명시하고, 바로 이어서 `layoutSizingHorizontal = 'FILL'`을 다시 지정한다. `resize`를 부르면 FIXED로 돌아가기 때문이다.
- 컴포넌트 속성(값, 아이콘 표시, 아이콘 교체)은 `setProperties`로 넣는다. 인스턴스 안의 텍스트·자식을 직접 고치지 않는다.
